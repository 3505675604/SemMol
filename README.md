# SemMol

Semantic-level molecular learning with a dynamic center library (DCL) and anchor-center soft matching (ACSM).

This implementation follows the manuscript method with explicit mathematical corrections. It uses scratch 1D/2D/3D encoders, one shared MLP projection, ordinary K-means/EMA centers, cosine top-M retrieval, normalized softmax weights, raw weighted-center fusion, and a property head over the anchor plus retrieved semantics. Full implementation choices and the manuscript corrections are documented in [docs/method_implementation.md](docs/method_implementation.md).

No electron-density generation is included. The structural pipeline never synthesizes or stores a proxy electron cloud. The optional QM extension reads externally computed quantum-mechanical grids with identity, charge/spin, units and provenance checks; it never fabricates missing grids.

The source and data contracts changed. Old independently projected or promolecular-density artifacts must not be silently reused. No benchmark results or pretrained weights have been regenerated by these code changes.

## Environment

Run production training on Linux with CUDA. Python and dependencies are pinned to the reported software generation:

```bash
conda env create -f environment.yml
conda activate semmol
python -m pip install --only-binary=:all: torch-scatter torch-sparse torch-cluster \
  -f https://data.pyg.org/whl/torch-2.1.0+cu121.html
python -m pip install -e . --no-deps
```

The optional logging and SHAP dependencies are listed in `requirements.txt`. CPU tests can use the matching PyTorch 2.1 CPU wheel and PyG CPU extension wheels; do not mix CPU and CUDA extension builds. Training entry points derive the device from `LOCAL_RANK` under torchrun.

## Prepare pretraining data

Use the official PCQM4Mv2 training pool and its DFT geometry SDF. The SDF has training molecules only; the full source dataset and the geometry-eligible training pool are different populations.

```bash
python scripts/preprocess/prepare_pcqm_manifest.py \
  --dataset-root data/raw/PCQM4Mv2 \
  --output data/processed/pcqm/source_manifest.parquet

python scripts/preprocess/filter_pcqm.py \
  --source-manifest data/processed/pcqm/source_manifest.parquet \
  --output-dir data/processed/pcqm/manifests \
  --target-sizes 1000000 3000000 \
  --smiles-col smiles --gap-col homolumogap \
  --source-index-col source_index --official-split-col official_split \
  --selection-mode exact
```

Selection is scaffold-aware, diversity-ranked, and gap-stratified. Exact max-min ranking is expensive at large scale; use frozen released source indices when reproducing an existing experiment. The explicit `approximate` mode is an engineering variant, not an unqualified claim of global exact FPS. Selection manifests record the algorithm, seed and scope. HOMO-LUMO gap is used for subset construction, not as a pretraining target.

Train one frozen ESPF vocabulary from the selected pretraining pool and use it for every downstream dataset:

```bash
python scripts/preprocess/build_espf_vocab.py \
  --input <selection_manifest.parquet> \
  --output-dir data/processed/pcqm/tokenizer --smiles-col canonical_smiles

python scripts/preprocess/generate_3d_conformer.py \
  --input data/processed/pcqm/source_manifest.parquet \
  --manifest <selection_manifest.parquet> --source-index-col source_index \
  --sdf-ordinal-col train_ordinal \
  --official-sdf data/raw/PCQM4Mv2/pcqm4m-v2-train.sdf \
  --output-dir data/processed/pcqm/geometry --num-conformers 1

python scripts/preprocess/build_pcqm_store.py \
  --selection-manifest data/processed/pcqm/manifests/pcqm_selection_CURRENT.json \
  --geometry-dir data/processed/pcqm/geometry \
  --tokenizer-dir data/processed/pcqm/tokenizer \
  --output-dir data/processed/pcqm/store --target-sizes 1000000,3000000

python scripts/preprocess/validate_processed_store.py \
  --store-dir data/processed/pcqm/store --full
```

The official-geometry path is the default. A missing/failed official source does not silently become ETKDG: fallback must be requested with `--allow-etkdg-fallback`. For an explicit generated-geometry ablation use `--geometry-source etkdg`. These options generate atomic conformers, not electron densities. Geometry manifests retain source and failure information.

## Prepare downstream data

Place the exact raw MoleculeNet CSV versions under one directory. Generate standard Bemis-Murcko splits before building stores:

```bash
python scripts/preprocess/build_scaffold_splits.py \
  --raw-root <moleculenet_raw_root> --output-dir data/splits \
  --datasets bace bbbp clintox tox21 toxcast sider freesolv esol lipophilicity \
  --frac 0.8 0.1 0.1

python scripts/preprocess/build_moleculenet_store.py \
  --raw-root <moleculenet_raw_root> --split-root data/splits \
  --tokenizer-dir data/processed/pcqm/tokenizer \
  --output-root data/processed/moleculenet \
  --datasets bace bbbp clintox tox21 toxcast sider freesolv esol lipophilicity \
  --num-conformers 1
```

All empty Murcko scaffolds form a single group. Whole groups are shuffled with a fixed seed and allocated toward 80/10/10 counts; exact fractions can be infeasible without breaking groups. Actual counts, invalid rows, source hashes and scaffold membership are saved. Historical modified-connectivity splits are archived under `data/splits/legacy_modified/` and are not current paper splits. Rebuild from the actual CSVs; moving historical indices does not create new results.

The main experiment uses one lowest-energy conformer. Build a separate store with `--num-conformers 4` for the multi-conformer experiment. Optimized candidates are filtered by an energy window and selected for heavy-atom RMSD diversity. Do not mix stores or report a default three-conformer run as a single-conformer experiment.

## Eight-GPU pretraining

The two production pretraining configurations retain eight processes and use ten epochs:

```bash
bash scripts/pretrain/run_pretrain.sh configs/pretrain/pretrain_1m.yaml
bash scripts/pretrain/run_pretrain.sh configs/pretrain/pretrain_3m.yaml
```

`world_size` is the total GPU/process count. For multiple nodes set `NNODES`, `NODE_RANK`, `MASTER_ADDR` and `NPROC_PER_NODE` consistently. Do not pass a fixed `--device cuda:0` under torchrun. `train.batch_size` is per rank; the effective batch also depends on world size and accumulation. Actual wall time is measured, not copied from the manuscript.

The runner resolves the same ACSM temperature and epsilon for matching and loss, writes complete runtime configuration, and saves architecture/anchor identity with checkpoints. Without a validation loader, use the produced `*_latest.pt`, not a nonexistent `*_best.pt`.

## Downstream supervised fitting and anchor variants

```bash
bash scripts/finetune/run_finetune.sh configs/finetune/bace.yaml
bash scripts/finetune/run_finetune.sh configs/finetune/bace_anchor_2d.yaml
bash scripts/finetune/run_finetune.sh configs/finetune/bace_anchor_3d.yaml
```

All supplied pretraining and downstream configurations use eight GPUs, including the small/debug pretraining presets. Downstream names without a suffix, such as `configs/finetune/bace.yaml`, already select eight GPUs; `_8gpu.yaml` names remain compatible alternatives with separate experiment names. Batch size is per rank, and the effective batch includes all eight ranks and accumulation steps. CPU integration tests override this explicitly with one process.

Each benchmark runs ten distinct supervised seeds. The model/anchor, input modality and pretrained center-library keys must match. Pretrain configurations for 2D/3D anchors are supplied under `configs/pretrain/`. Validation selects the checkpoint; test is evaluated after selection and does not update centers. Ten training seeds are not ten CV folds.

For SemMol without external pretraining, run train-only semantic alignment followed by supervised fitting:

```bash
python scripts/finetune/run_two_stage.py configs/finetune/bace.yaml \
  --output-dir outputs/two_stage/bace --prepare-only
# Inspect the generated protocol/configs, then omit --prepare-only to execute.
```

Both stages default to eight GPUs. This protocol performs one explicitly seeded alignment initialization on the registered outer training view, followed by ten independently seeded supervised fits. It does not describe the entire two-stage process as ten independent pretraining runs. No validation/test samples enter alignment or DCL updates.

## Hyperparameter search

```bash
python scripts/hyperparam/run_grid_search.py \
  --base-config configs/finetune/bace.yaml \
  --grid configs/hyperparam/finetune_sensitivity.yaml \
  --output-dir outputs/hyperparam/bace --mode finetune --cv-folds 10
```

Downstream ten-fold model selection partitions only the outer training pool by scaffold groups. Outer validation/test are excluded. The inner-fold entry point uses train and inner-validation loaders only; it emits development metrics rather than fabricated test scores. Fold sidecars record membership and hashes. Pretraining sensitivity is a separate diagnostic; changing K/projection architecture requires a matching new pretraining checkpoint and cannot be tested by partially loading incompatible weights.

## External QM grids only

The optional store-builder argument is `--external-density-dir ROOT`. Supply `ROOT/pcqm/SOURCE_INDEX.npz` or `ROOT/bace/SOURCE_INDEX.npz` etc. Grid shape is `[1,32,32,32]`, spacing 0.75 angstrom, density units electron/angstrom^3. The reader validates molecular identity, charge/spin, calculation method, basis, software/source provenance and electron integral. See `src/molecular/electron_density.py` for the complete contract.

Missing or invalid external files are explicit failures for requested QM inputs. Omitting the argument disables QM storage. There is no Gaussian/promolecular generator, fallback electron cloud or generator CLI. This contract validates supplied data; it does not prove an external calculation is scientifically accurate.

## Diagnostics and result tables

Shared-parameter gradient diagnostics refer to actual learned projection parameters, never EMA center buffers. Negative statistics distinguish all candidates from the final threshold-selected training negatives. Variance ratios are descriptive proxies, not inferred noise probabilities. POR@Scaffold is true-label top-k enrichment, not structural similarity.

SHAP explains the anchor and retrieved semantic-center blocks at the property head. It is not raw-input atom attribution or a percentage of physical information. Reports distinguish selected top-30 analysis from all-foreground summaries and preserve output-space/background metadata.

Generate table cells from measured per-seed results instead of copying manual means:

```bash
python scripts/evaluate/summarize_results.py \
  --input <measured_runs.csv> --output outputs/tables/summary.json \
  --expected-seeds 10 --model SemMol --baseline <baseline_name>
```

CSV columns are `model,dataset,metric,unit,seed,value,split_sha256`. The tool rejects duplicate/missing seeds and mismatched splits; cross-task RMSE comparisons use dimensionless paired relative changes rather than adding different physical units.

## Validation

```bash
python -m pytest -q
```

Tests include real small-data tokenization, canonical graphs, conformers, pretraining forward/backward, downstream gradients, mathematical counterexamples, data contracts and protocol isolation. CPU tests do not validate eight-GPU/NCCL behavior or reproduce published benchmark scores. See `docs/method_implementation.md` for remaining manuscript corrections and compatibility boundaries.
